This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`linux-audit.sh` is a bash script that audits remote Linux servers via SSH, collecting system information, performance metrics, and SAR (sysstat) historical data. It generates both terminal output with colored alerts and a standalone HTML report.

## Running the Script

```bash
# Basic usage
./linux-audit.sh hostname_or_ip

# With SSH options
./linux-audit.sh -u admin -p 2222 -i ~/.ssh/id_rsa hostname

# With password authentication (requires sshpass)
./linux-audit.sh -u admin -P hostname                   # interactive prompt
SSHPASS='secret' ./linux-audit.sh -u admin -P hostname  # non-interactive (preferred)
./linux-audit.sh -u admin -P 'secret' hostname          # discouraged (visible in ps)
```

Exit codes follow the Nagios convention: 0 no alert, 1 WARNING, 2 CRITIQUE, 3 error (bad arguments, SSH unreachable or lost mid-run, report not writable).

No build or test commands - this is a single bash script. Useful checks: `bash -n linux-audit.sh`, `shellcheck -S warning linux-audit.sh` (only SC2155 and one intentional SC2183 in `print_line` remain), and an end-to-end run against a local `sshd` (`/usr/sbin/sshd -p 2222`) with SAR data generated by `/usr/lib/sysstat/sadc`.

## Architecture

The script (~1950 lines) is organized into numbered sections:

| Section | Lines | Purpose |
|---------|-------|---------|
| 1 | ~1-85 | Global variables, thresholds, colors |
| 2 | ~86-320 | Utility functions (print_*, SSH plumbing, is_int/is_num, alerts) |
| 2B | ~322-790 | HTML generation functions (html_*), SVG CPU chart |
| 3 | ~792-1528 | Data collection functions (collect_*) |
| 4 | ~1530-1724 | SAR/sysstat data collection and analysis |
| 5 | ~1726-1765 | Alert summary generation |
| 6 | ~1767-end | Main function, argument parsing |

### Key Functions

- `build_ssh_args()` / `run_ssh()` - SSH options held in the `SSH_ARGS` array (paths with spaces stay intact), `--` before the destination, `sshpass -e` in password mode
- `open_ssh_master()` / `close_ssh_master()` - One multiplexed connection (`ControlMaster`, socket in `WORK_DIR`) reused by every command; falls back to direct connections if it cannot be opened
- `ssh_exec()` - Sends the command on stdin to remote `sh -s`, wrapped in `{ ... } </dev/null` with a prelude (`LC_ALL=C`, `/sbin:/usr/sbin` appended to `PATH`). Works whatever the login shell (bash, tcsh, fish). On SSH transport error (rc 255) it drops a marker file in `WORK_DIR`
- `check_ssh_alive()` - Called after each collection step: aborts the audit (exit 3, no report) if the marker exists, rather than producing a report filled with empty values
- `detect_remote_cmds()` / `remote_cmd_exists()` - One inventory of remote commands (`REMOTE_CMDS`) instead of one SSH round trip per check
- `detect_distro()` - Detects Linux distribution (RHEL, Debian, Ubuntu, Oracle, etc.)
- `detect_sar_path()` - Locates SAR data files once and stores them in `SAR_PATH` (supports old and new sysstat paths)
- `collect_*()` - Data collection functions:
  - `collect_system_info()` - OS, kernel, hostname, uptime
  - `collect_cpu_info()` - CPU model, cores, current usage
  - `collect_memory_info()` - RAM usage, buffers, cache
  - `collect_swap_info()` - Swap usage and top swap consumers
  - `collect_load_info()` - Load averages vs CPU count
  - `collect_disk_info()` - Filesystem usage with type column
  - `collect_network_info()` - Interfaces, IPs, routing
  - `collect_process_info()` - Top processes by CPU/memory/disk I/O
  - `collect_sar_data()` - Historical SAR metrics
- `html_*()` - HTML generation helpers that append to `HTML_CONTENT` global variable
- `generate_cpu_sar_chart()` - Generates SVG stacked area chart from SAR CPU data (shows %user, %system, %iowait, %idle)
- `analyze_sar_io_history()` - Detects I/O anomalies from historical SAR data: one `sar -d -p` and one awk pass per file on the remote side, columns found by name on the header line (the timestamped line containing a `DEV` field)

### Data Flow

1. `umask 077`, temporary `WORK_DIR`, multiplexed SSH master opened, remote command inventory and SAR path detected once
2. Each `collect_*()` function runs commands via `ssh_exec()`; `check_ssh_alive` runs after each one
3. Remote output is parsed once into normalized lines, then a single loop prints the console row and appends the HTML row (e.g. I/O data is normalized to `device rMB/s wMB/s await %util` whether it comes from iostat or `/proc/diskstats`)
4. HTML content accumulated in `HTML_CONTENT` variable (`html_append` is a no-op when `HTML_OUTPUT` is empty)
5. At end, HTML written to `YYYYMMDD-Hostname-audit.html` (write verified); exit code derived from the alerts

## Privilege Requirements

No root required on either machine:
- **Local machine**: any user with `ssh`/`gzip` available can run the script
- **Remote machine**: any SSH user works; all collected data comes from world-readable sources (`/proc/meminfo`, `/proc/cpuinfo`, `/proc/loadavg`, `/proc/diskstats`, `/proc/net/dev`, `df`, `ps`, `uname`, etc.)

Two limitations apply for non-root remote users:
- **Disk I/O per process** (`collect_process_info`): `/proc/[pid]/io` is only readable by the process owner or root. A non-root user will only see I/O stats for their own processes. The script handles this gracefully with `[ -r $p/io ] || continue`.
- **SAR data** (`collect_sar_data`): SAR files in `/var/log/sa/` or `/var/log/sysstat/` may require membership in the `adm` group (Debian/Ubuntu) or explicit read permissions (RHEL/CentOS). If unreadable, the SAR section is skipped with a warning.

The default SSH user is `root` (convenience default only), overridable with `-u`.

## Technical Constraints

### Bash 3.x Compatibility (RHEL6 Support)
- No associative arrays (`declare -A`)
- No lowercase/uppercase expansion (`${var,,}`, `${var^^}`)
- No `+=`, `mapfile`/`readarray`, `local -`; indexed arrays and `read -a` are fine
- Alerts are stored as newline-separated strings (`ALERTS_CRITICAL`, `ALERTS_WARNING`), never `|`-separated: mount points and device names may contain `|`
- Multi-line remote scripts go in `read -r -d '' var <<'EOS' ... EOS` (quoted heredoc: no escaping). Avoid `$(cat <<EOF ...)`, which bash 3 parses badly. Values are passed as a prefix of shell assignments

### Remote Data Is Untrusted
- The audited server may be compromised: every remote value is either validated (`is_int`, `is_num`, regex in awk) before arithmetic, comparisons or insertion into an attribute or SVG, or escaped with `html_escape`
- `html_table_row` escapes every cell; trusted internal HTML (badges) goes in its third argument
- The remote hostname is sanitized (`tr -cd 'A-Za-z0-9._-'`) before use in local file names

### SAR Data Parsing
- Always use `LC_ALL=C` for SAR commands to ensure consistent US format (dot decimal separator, MM/DD/YY dates)
- Column detection must be dynamic - sysstat versions have different column layouts for metrics like `await` and `%util`
- Support both old (`/var/log/sa/sa01`) and new (`/var/log/sysstat/sa20260125`) SAR file naming
- I/O anomaly detection uses multiple criteria: high %util (>= `THRESH_SAR_UTIL`, 80%) OR high await (>= `THRESH_SAR_AWAIT`, 30ms), not just one metric
- With `-p`, sysstat >= 12 prints `DEV` as the **last** column; old versions print it second, with an optional AM/PM field after the time
- iostat: when `await` is split into `r_await`/`w_await` (sysstat >= 12), weight it by `r/s` and `w/s` (a plain average halves the latency of a write-only disk)

### Subshell Variable Scope
- Avoid `echo | while read` pattern - variables set in subshell are lost
- Use `while read <<< "$var"` (here-strings) instead
- Functions that must set globals (`detect_sar_path`, `detect_remote_cmds`) are called directly, never inside `$(...)`; `ssh_exec` reports transport failures through a marker file for the same reason

## Threshold Configuration

Alert thresholds are defined at the top of the script (lines ~26-44):
```bash
THRESH_RAM_WARN=75    THRESH_RAM_CRIT=85
THRESH_SWAP_WARN=30   THRESH_SWAP_CRIT=50
THRESH_CPU_WARN=70    THRESH_CPU_CRIT=85
THRESH_LOAD_WARN=1.0  THRESH_LOAD_CRIT=1.5
THRESH_IOWAIT_WARN=15 THRESH_IOWAIT_CRIT=25
THRESH_DISK_WARN=80   THRESH_DISK_CRIT=90
THRESH_DISKIO_UTIL_WARN=70  THRESH_DISKIO_UTIL_CRIT=90  THRESH_DISKIO_AWAIT_WARN=50
THRESH_SAR_UTIL=80    THRESH_SAR_AWAIT=30
```

## Output Files

The script generates:
Both files are created with `umask 077` (mode 0600).

- `YYYYMMDD-Hostname-audit.html` - Standalone HTML report with embedded CSS, includes:
  - Interactive sections with collapsible details
  - SVG CPU history chart (stacked area: %user, %system, %iowait, %idle)
  - Color-coded alerts matching terminal output
- `YYYYMMDD-Hostname-sar.gz` - Compressed SAR data export (if sysstat available)
